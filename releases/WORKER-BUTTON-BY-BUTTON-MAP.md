# خريطة النظام الكاملة — كل زر وكل خطوة (AYROVI Worker)

**تاريخ الوثيقة:** 11 سبتمبر 2026
**نسختك المثبتة حاليًا:** v1.7.3 (64) — بناءً على سلوك لقطاتك
**حالة هذه الوثيقة:** توثيق صادق من الكود المصدر سطرًا بسطر. لا يوجد أي بناء أو إصدار جديد حتى توافق على الجدول في القسم 6.

---

## 1) شاشة تسجيل الدخول (SIGN IN)

| العنصر | ماذا يفعل بالضبط |
|---|---|
| حقل EMPLOYEE CODE | رقم العامل |
| حقل PASSWORD / PIN | كلمة المرور أو الرمز السري |
| زر USE PIN ⇄ USE PASSWORD | تبديل نوع الحقل الثاني ويمسح ما فيه |
| زر SIGN IN | يتفعل فقط بعد ملء الحقلين → يتحقق من الخادم |
| أيقونة ⚙ (في ترويسة هذه الشاشة فقط) | DEVICE SETUP — يعرض رمز الجهاز (Device Code) لتسجيله عند المشرف |

**متى تُعرض هذه الشاشة إجباريًا؟**
1. أول فتح للتطبيق.
2. بعد SIGN OUT.
3. **عند انتهاء صلاحية الجلسة لدى الخادم (AUTH EXPIRED)** — هذا سلوك أمني من الخادم؛ لا يمكن لأي تطبيق تجاوز بدون مخالفة أمنية.

## 2) الرئيسية (HOME) — الشاشة الأولى بعد الدخول

الترويسة: AYROVI · ONLINE · المحطة · اسم العامل — **بدون أيقونة إعدادات** (عمدًا).

| الزر | يفتح | التفصيل الدقيق |
|---|---|---|
| **RECEIVING** (بطاقة كبيرة + نقطة خضراء إن كان جديد + "N WAITING") | شاشة الاستقبال (استعراض فقط) | متاح فقط إذا كانت مهمة الاستقبال مُسندة لك؛ غير ذلك يظهر السبب (OFFLINE / CHECKING / NOT ASSIGNED) |
| **OCR** (أيقونة كاميرا) | أداة المسح مباشرة + فتح كاميرا OCR فورًا (هاتف) | في نسختك تمر عبر الأداة التي فيها البطاقة التمهيدية والسهم الجانبي (القسم 4) |
| **QR CODE** (أيقونة QR) | أداة المسح مباشرة + هاتف: كاميرا QR فورًا / CT40: الزناد الجانبي | نفس الأداة، بدون كاميرا للـ OCR |
| **RAPPORT** | تقرير الاستلام (جلسة RCV المفتوحة) | شاشة مستقلة |
| **SETTINGS** | نافذة الإعدادات | نافذة فوق الشاشة الحالية (تغيير العرض/قفاز/سجل التقرير/تسجيل خروج الوضع) |
| **CONTINUE RCV-xxxxxx** | نفس بطاقة RECEIVING | يظهر فقط عند وجود جلسة استقبال نشطة |
| **YOUR INSTRUCTION** + MARK INSTRUCTION DONE | تعليمات المشرف (هاتف فقط) | لوحة نصية بزر إنجاز |
| **REFRESH QUEUE** | تحديث قائمة العمل | ثابت سفلي أيسر |
| **SIGN OUT** | خروج لشاشة الدخول | ثابت سفلي أيمن |
| **STATIONS** (محطاتك الأخرى: TEMP STORAGE / SORTING / PACKING / SHIPPING / TRACE) | شاشة كل محطة مستقلة | لم تُمس في هذه الشكوى |

## 3) شاشة الاستقبال (RECEIVING) — استعراض فقط، لا مسح

| العنصر | السلوك |
|---|---|
| عنوان RECEIVING | — |
| TO DO | بطاقات المنتج/الكارتون المرسلة من الخادم + EXPECTED/RECEIVED/REMAINING — **غير قابلة للنقر** (عمدًا) |
| ISSUES | بطاقات المشاكل: NOT MATCHED المسجل / فروقات مفتوحة / NEEDS REVIEW (تصنيف يحتاج مراجعة مشرف) |
| DONE | بطاقة الجلسة: SESSION RCV-xxxxxx + UNITS n/n + CARTONS n/n |
| BACK (الثابت السفلي) | → **الرئيسية** مباشرة |
| ☀ (الثابت السفلي) | GLARE BOOST — تعزيز الشمس |
| نقطة الاتصال + BATT | أخضر = متصل؛ BATT تظهر تحت 15% |

## 4) أداة المسح (SCAN) — ما يفتحه زر QR CODE أو OCR — هنا كل مشاكلك

هذه الحقيقة التي عشتَها في اللقطات، عنصرًا عنصرًا، كما هي **في الكود الفعلي**:

| # | ما تراه | ما يفعله الكود حاليًا | حكمك عليه (صحيح) |
|---|---|---|---|
| 1 | الترويسة مكتوب فيها **"RECEIVING"** وأنت في الماسح | الشاشة نفسها تُستخدم لمسارين (الاستقبال والماسح) والعنوان ثابت | ❌ عنوان خاطئ ومربك — سبب إحساس "التداخل" |
| 2 | بطاقة **"SCAN — Scan a product or a carton. The device matches it automatically."** | رسالة INFO تُضاف عند كل فتح للأداة | ❌ "مقدمات" — طلبت الفتح بدون أي مقدمة |
| 3 | شريط أزرق + عنوان **SCAN PRODUCT OR CARTON** | عنوان اللوحة | ✓ مقبول |
| 4 | **READY TO SCAN** + رسمة هاتف/CT40 | حالة الانتظار | ✓ |
| 5 | سطر **LAST: 7630073610160 ! 01:25** | آخر قراءة + الوقت + العلامة (✓ نجاح / ✕ خطأ / ! تحذير / • محايد) | ✓ |
| 6 | زر **SHOW TRIGGER** → يصير **TRIGGER SCAN** (هاتف فقط) | زر المسح اليدوي — نقرة واحدة | ✓ (هذا ما ينبقي الجلسة بدون كاميرا دائمة) |
| 7 | **السهم الجانبي ◀** على حافة الشاشة اليمنى | يفتح درج SCAN TOOLS: QR/BARCODE · OCR · MANUEL · CT40 · FERMER | ❌ طلبت حذفه/تعديله |
| 8 | الثابت السفلي **BACK TO RECEIVING** | يعيدك إلى **شاشة الاستقبال** (وليس الرئيسية)؛ ثم BACK ثانية → الرئيسية | ❌ "يمر عبر receving ويتعلق هناك" — بالضبط ما شكيت منه |
| 9 | كاميرا QR: مربع معتم + زوايا بيضاء + زر BACK | BACK هنا يغلق الكاميرا ويعود لـ READY فقط | ✓ |
| 10 | كاميرا OCR: شريط مسح + عند التقاط رمز صالح: الرمز + CONFIRM CODE | بدون رمز صالح لا يظهر شيء | ✓ |
| 11 | **نتيجة النجاح: وميض أخضر 250 ميلي ثانية** ثم عودة READY تلقائيًا | لمسة صفرية للمتابعة، لكن الفلاش أقصر من أن يُرى | ❌ "الكاميرا تغلق وحدها ولا تعطي حتى إشارة" — هذا هو السبب الحرفي |
| 12 | نتيجة الخطأ: شاشة **حمراء ثابتة** + NOT MATCHED + "The failure was logged." + BACK | تُسجل مرة واحدة؛ تزول بـ BACK أو بقراءة جديدة | ✓ (منطق عمل لا يُمس) |
| 13 | **RETRY LAST SCAN** (بعد فشل) | إعادة نفس القراءة الفاشلة | ✓ |

## 5) دورة الحياة — لماذا شعرت أنك "تعيد تسجيل الدخول" لكل فتح ماسح

الشرح الصادق، سببًا سببًا:

1. **زر BACK من الأداة يقتل حالة الأداة كليًا** (المسار يُدمَّر من الذاكرة). عدت بـ QR CODE = جلسة جديدة من الصفر.
2. **نسخة 64 أضافت "جلسة جديدة دائمًا"**: كل ضغطة QR CODE تصفّر أي جلسة مفتوحة (لعلاج "الصفحة القديمة") — النتيجة: تصفير إجباري عند كل دخول. حسّيتها كإعادة تسجيل.
3. **بطارية 7%**: أندرويد يقتل التطبيق في الخلفية بسهولة عند نفاد البطارية → تعود للرئيسية، وإذا كانت الجلسة منتهية لدى الخادم → شاشة الدخول (سلوك خادم أمني).
4. **AUTH EXPIRED من الخادم** → شاشة الدخول إجباريًا. هذا لا يمكن تعطيله (أمن).

## 6) جدول القرار — كل شكوى ↔ السبب الحقيقي في الكود ↔ الإصلاح المقترح

> **الحالة: مقترح فقط. مكتوب في مساحة العمل، غير مبني، غير مُصدر، ولن يُبنى إلا بكلمة "وافق" منك أو بتعديلك على أي بند.**

| # | شكواك | السبب الحقيقي (ملف/موضع) | الإصلاح المقترح v1.7.4 |
|---|---|---|---|
| 1 | "تفتح بمقدمات" | بطاقة SCAN التمهيدية + رسالة INFO في `AutoLane` (ReceivingHomeScreen) | حذف الاثنتيًا → الفتح **مباشرة على READY** |
| 2 | "زر جانبي احذفه أو عدّله" | `ScanToolsEdgeButton` + `ScanToolsDrawer` داخل شاشة الأداة | **حذفهما من هذه الأداة** (يبقى READY/كاميرا/نتيجة فقط) |
| 3 | "BACK يعيد لصفحة رئيسية وليس واجهة قديمة" + "يمر عبر RECEIVING ويتعلق" | منطق `if (lane) BackToReceiving else onBack` | **قاعدة واحدة: BACK → الرئيسية دائمًا** من أي مكان |
| 4 | "تداخل OCR/QR يمر عبر RECEIVING" | مسار SCAN يعيد استخدام شاشة الاستقبال نفسها + عنوان ترويسة ثابت "RECEIVING" | ترويسة الأداة تصير **"SCAN"** والاستقبال يبقى "RECEIVING" — فصل بصري كامل |
| 5 | "أضطر لإعادة تسجيل دخول لفتح السكان كل مرة" | تصفير openWith في v1.7.3 + قتل الحالة عند BACK | **استمرارية**: ضغطة QR CODE والأداة مفتوحة = **تستأنف كما هي** (آخر قراءة وجلستها) بدون تصفير ولا إعادة تسجيل — تُفتح من جديد فقط إذا كانت مغلقة فعلًا |
| 6 | "الكاميرا تغلق وحدها ولا تعطي حتى إشارة" | وميض النجاح 250ms | **1200ms** — وميض أخضر/أحمر يُرى بوضوح قبل عودة READY |
| 7 | "النظام غير مستقر" | إخراج إجباري من الشاشة إذا came قائمة مهام فارغة لحظيًا (شبكة ضعيفة/تحديث) | الإخراج فقط عند **حذف حقيقي** للمهمة من الخادم |

**ما لن يُغيَّر (منطق العمل والخادم):**
- التطابق التلقائي، التحقق، رسائل NOT MATCHED، "The failure was logged."، تسجيل الفشل مرة واحدة.
- إجبار تسجيل الدخول عند انتهاء صلاحية الجلسة (أمني — خارج سيطرة التطبيق).
- CT40: الزناد الجانبي الفوري كما هو.

## 7) المسارات كاملة خطوة بخطوة (بعد الإصلاح المقترح)

**مسار QR (هاتف):**
الرئيسية → QR CODE → أداة SCAN تفتح **مباشرة على الكاميرا** (بدون بطاقة/بدون سهم) → توجيه الملصق → **وميض أخضر واضح (1.2 ثانية)** → READY (زر TRIGGER للمتابعة، أو وجّه الملصق التالي بالضغط عليه) → BACK → **الرئيسية** مباشرة.

**مسار QR (CT40):**
الرئيسية → QR CODE → READY → الزناد الجانبي → وميض → زناد تالٍ… → BACK → الرئيسية.

**مسار OCR (هاتف):**
الرئيسية → OCR → كاميرا OCR مباشرة → رمز صالح → CONFIRM CODE → نتيجة → BACK → الرئيسية.

**مسار فشل:**
قراءة غير مطابقة → شاشة حمراء ثابتة: NOT MATCHED + "The failure was logged." (مرة واحدة) → BACK أو قراءة جديدة.

1. توافق على الجدول أعلاه (أو تعدّل أي بند) — **قبل أي كود إضافي**.
2. بناء تحقق كامل واحد: اختبارات الوحدات + lint + androidTest + APK (~15–25 د لأول بناء على البيئة الباردة).
3. إصدار **v1.7.4 (65)**: commit → push (master + arena/ux-restructure) → CI → APK + تقرير يحتوي هذه الخريطة نفسها.

**تعهد واضح:** لا بناء، لا إصدار، لا "حلول وقتية" — التنفيذ الحرفي لما يظهر في القسم 6 بعد موافقتك فقط، وإن خالف أحد البنود النتيجة الفعلية في الجهاز أُصلحه دون نقاش.
